# Content verification

Generated by `python tools/verify/report.py` from `audit/raw/verification.json`.
Reproduce from scratch with:

```bash
node tools/extract-items.mjs && python tools/verify/verify_items.py && python tools/verify/report.py
```

## Method

- **Source of items.** `tools/extract-items.mjs` loads each unit page in headless Chrome and reads the `BANKS`, `T` and `VQB` arrays exactly as the browser sees them (`audit/raw/items.json`). There are **no problem generators** in the site: every practice and test item is a static object, so "every static item once" covers the whole bank. The 10,000-draw requirement is applied to *set assembly* instead (below).
- **Independent answers.** `tools/verify/handlers.py` re-solves each item from its own text with SymPy (exact rationals, `solveset`, `linsolve`, `reduce_inequalities`, polynomial arithmetic). It parses the raw strings itself and never calls or imports site code (`isMatch`, `formatEq` and the rest are not used).
- **Items no parser covers** (word problems, definitions, pictures) have hand-written independent solutions in `tools/verify/manual.py`: an equation SymPy solves, a definition, or a reading of the drawn SVG recovered in maths coordinates by `tools/verify/svgread.py` (contact sheets in `audit/raw/svgs/`).
- **Comparison.** The site key is parsed separately into the same type (number, solution set, interval, point, expression) and compared for mathematical equality, so `x = 5` vs `5` or `2x+3` vs `3+2x` are not counted as mismatches. A key that does not parse at all is a mismatch.
- **Also checked:** duplicate items within a bank or test pool; 10,000 seeded draws (seed 219) of every 5-problem practice set and every assembled practice test, mirroring the site's slice logic; special-case type vs topic label (5.4/6.4 must be no-solution/all-reals, 5.1–5.3/6.2–6.3 must not); malformed `<sup>` markup; scratch work left in keys or explanations; explanations that contradict the key; vocabulary quiz answer indices and duplicate options.

## Limits of this verification

- Picture items were checked by recovering coordinates from the SVG source, plus a visual pass over the rendered contact sheets. Parabolas are drawn as straight-segment polylines, and several y-axes have unevenly spaced labels; only differences that change the answer are counted as mismatches.
- "Correct" for words-based items (definitions, yes/no) is judged against standard Algebra 1 usage; where usage varies the item is listed as ambiguous rather than wrong.
- Whether a student's *typed* answer is accepted is a separate question, covered by the checker corpus (`tests/checker-corpus.json`).
